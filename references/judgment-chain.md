# judgment-chain — 判断链手册(v8.0,全员必读)

> **你是谁**:你是判断链上的一个写手——四个节点写手(node-quality / node-state / node-odds / node-path)之一,或 decision-writer。
> **读什么**:本手册 + **你自己那一份节点手册**,只此两份。别人的节点手册不读,别人的原始证据不重推。
> **产什么**:`runs/{date}/` 下你那一个 md 文件——顶部一个 fenced YAML verdict 块(机器唯一数据源)+ 正文(verdict 先行、最硬证据制)。
>
> 本手册是**链结构的唯一真理源**:四问定义、决策层规则、摘要层装配、写作规范。节点手册只讲"本节点的证据怎么看",链规则一律以本手册为准。

---

## §1 总公式与四问定义

### 1.1 总公式

> **投资价值 = 状态后验 × 赔率 × 路径可承受性** ——**乘法**,任一为"差"即拉低整体。
> **长期结果 = 更新能力 × 等待能力 × 右尾捕捉 × 左尾毁灭风险。**

它把"是不是好公司"这个错问题,替换成三个分开的问题:**正在变好吗 → 已被价格吸收了吗 → 兑现前扛得住吗**,并据此分出 **好公司 ≠ 好下注 ≠ 好价格**。

### 1.2 链结构

```
证据层(具名机制,只产证据不产结论)
  data_snapshot / audit_report / peer_analysis / capital_flow / PDF 精析 / 舆情
        │
四问中间层(各一处权威,四个节点写手)
  ①质地 是不是好公司?   ②状态 在变好吗?   ③赔率 贵不贵?   ④路径 扛得住吗?
        │
决策层(一处,decision-writer)
  三元组[状态|赔率|路径]乘法 → 行动档位 + 该等什么 + 证伪;好公司? 直接引用①
        │
摘要层(机器装配:决断卡/赚钱面板/Top3/主页 metadata;人工只写 3-5 句导读)
```

**写作顺序 ≠ 章节顺序**:第一波 ①质地 ∥ ③赔率 ∥ ④路径 并行 → 第二波 ②状态(四层验证第④关引用赔率 verdict)→ 决策层。排版是装配脚本的事。

### 1.3 四问定义与 verdict 取值域

| 节点 | 决断卡问句 | verdict 取值域 | 全链唯一权威内容 | 章预算 |
|---|---|---|---|:--:|
| ①质地 quality | 是不是好公司 | 好 / 部分好 / 不好 | 五个子判定(生意模式赚钱吗 / 赚钱质量真吗 / 护城河存在吗 / 管理层可信吗 / 财务底子稳吗),✓ ⚠️ ✗ 三态;赚钱面板自选指标 | ≤70 行 |
| ②状态 state | 在变好吗 | ↑变好+证据确认 / ↑变好但仅注意力·未确认 / 横盘 / ↓变差 | **临界点(=该等什么)**;实锤 vs 传闻分级;身份切换 | ≤60 行 |
| ③赔率 odds | 贵不贵 | 便宜(有 slack) / 合理 / 已 price-in / 买完完美未来(无 slack) | **区间锚 [SOTP, DCF] 两端与同向标记**;估值类红旗归家 | ≤70 行 |
| ④路径 path | 扛得住吗 | 可承受 / 高尾险·不可承受 | **左尾清单**、**证伪/退出清单**、高信仰体检、回报路径成本 | ≤60 行 |
| ⑤决策 decision | 怎么办 | 行动档位人话一句 | **行动档位、仓位、三分结论、封顶检查结果** | ≤50 行 |

**★质地是筛选信号,不进乘法**:①不参与三元组相乘,决策层的"好公司?"直接引用①的 verdict,不再自判。理由:好公司 ≠ 好下注,把质地乘进去等于用长期资产质量掩盖当期赔率与路径。

**证据不足时**:verdict 写"不确定",并明写缺哪条证据、要等什么才能定——不许用中庸词把不确定包装成判断(见 §4.3、§4.4)。

### 1.4 一处权威表(唯一出处;别处只能引用)

| 内容 | 唯一出处 | 其他章的正确写法 |
|---|---|---|
| 该等什么 / 临界点 | ②状态 | 引用一句 + 指向②(决策层可复述为"等什么") |
| 贵不贵 / 估值锚 | ③赔率 | 引用 verdict 或锚区间数字,不重算 |
| 左尾情景、证伪条件 | ④路径 | 决策层的"证伪/退出"从④取,不新编 |
| 仓位、行动档位 | ⑤决策 | 任何节点都**不许**写"建议仓位""可回避""可买入" |
| 好公司? | ①质地 | 决策层引用,不再自判 |
| 红旗清单(全部条目) | 附录D(机器合并 audit + 节点提名) | 每条红旗只在其**归属节点**叙述一次 |
| "谁在买"(筹码/资金流底稿) | 附录C | ③④引用,不复制表 |

## §2 决策层规则(decision-writer 权威,其他写手不得代行)

### 2.1 决策三元组

`[状态后验 | 赔率 | 路径可承受性]` ——三个字段各取 §1.3 的 verdict,**原样搬运,不改口径**。

### 2.2 三元组 → 六档行动档位映射

| 状态后验 | 赔率 | 路径 | → 行动档位 |
|---|---|---|---|
| ↑确认 | 便宜 / 合理 | 可承受 | **核心仓**(高 λ 高 payoff) |
| ↑未确认 | 已 price-in / 买完完美未来 | 高尾险 | **等证据临界(观察)** 或 **期权仓(小)**,看右尾大小 |
| ↑ | 买完完美未来 | 可承受 | **不追高(贵但优质)** / **减仓** |
| ↓变差,或(买完完美未来 且 高尾险) | — | — | **回避** |

六档含义:

- **核心仓**——高确信、有 slack、路径可扛 → 给足合法仓位。
- **期权仓(小)**——右尾大但未确认 → 小仓博右尾,**叙事越远仓位越小**。
- **等证据临界(观察)**——λ↑ 但证据未达临界 / 价格无 slack → 高质量等待;**必须给明确等待事件 + 退出条件**,否则就是"资本钝化、套牢自我安慰"。现金 = 等待的选择权。
- **不追高(贵但优质)**——好公司已 price-in;不回避标的本身,只是现价不入场。
- **减仓 / 回避**——路径不可承受 / 买完完美未来无 slack / 状态向下。

### 2.3 ★封顶规则(硬规则,机器可检)

**任一致命红旗触发 → 行动档位强制封顶「回避」**,不论三元组算出什么,也不论故事多动人。致命红旗 = audit 静默机算的 🔴(旧"六项快筛"阈值已并入 `financial_audit.py`,报告零篇幅:非标审计意见 / 已证实财务造假 / 商业模式不可持续 / 持续经营重大疑虑 / 重大法律合规可能停业 / 🔴 ≥2 条)。

决策块必须写**封顶检查结果**:触发与否 + 触发时是哪条。未触发也要显式写"无致命红旗,不封顶"。

### 2.4 ★区间锚两端同向规则

估值锚是**区间** `[SOTP, DCF]`,不是单点数字(两端怎么算见 `node-odds.md`)。

- **两端同向** → 赔率判定成立,按判定进乘法。
- **两端不同向**(一端说贵、一端说不贵)→ 赔率 verdict 标注「**取决于口径**」并写明分歧原因(两把尺子量的是不同的东西),**且决策层档位保守一档**(如"期权仓"→"等证据临界","不追高"→"减仓")。
- 旧 v4.2 的"两法差异 >20% 必须重做 DCF"红线**已废除**——分歧是信息,不是错误,摊开展示即可。

### 2.5 三分结论

**好公司?**(← 引用①质地 verdict:好 / 部分是 / 否)· **好下注(现价)?**(状态×赔率×路径的乘积)· **好价格?**(有无 pricing slack ← ③赔率)。三个分开判,各带一句依据。

### 2.6 右尾纪律(决策层判,不在②③④重推)

- **右尾识别清单**(逐件 ✓/✗):需求真实可延展 / 难替代的提价权 / FCF 自我造血 / 利润率持续提升 / 估值起点偏低。
- **幂律来源**:需求函数巨变 / 供给短期刚性 / 瓶颈节点 / 规模越大越强 / 客户验证正反馈 / 资本市场提高终局后验 / 自强化循环 —— 判它是不是"幂律生成器节点"。
- **陷阱**:涨多 ≠ 继续涨;热 ≠ 每个都是右尾;用平均估值看幂律赢家会觉得"永远贵"。
- **心法**:不在左尾毁灭 + 能识别右尾 + **右尾被证据确认时才敢给足合法仓** + 右尾衰减时更新 + 不把曾经的右尾当永恒资产。
- **不为左尾放弃右尾**:右尾大而未确认 → 用"期权小仓 + 硬止损"表达,而不是一刀回避。

### 2.7 该等什么 / 证伪 / 退出

- **该等什么**:从②状态的临界点**引用**,决策层可加价格条件(如"回调至 X 元以内")。
- **证伪/退出**:从④路径的证伪清单**引用**;每条核心叙事至少 1 个可证伪指标。退出触发 = λ 下降 / 证据斜率转负 / 关键证伪指标命中 / 左尾事件发生。
- 证伪与退出条件必须**具体到可核销**(数字、时间窗、可观察事件),下一次增量复查(`--review`)会逐条核销。

### 2.8 仓位唯一出处

仓位只在决策层发声一次(如"总资金 ≤2-3% 期权小仓,设硬止损")。任何其他节点出现"建议仓位/建议回避/可以买入"都是越权,lint 与 reviewer-logic 会拦。

### 2.9 信仰陷阱五弊端自检(决策层收尾逐条 ✓)

① 把"好公司"当"好股票"? ② 把远期可选项当当期现金流? ③ 把坏消息当短期噪音、失去证伪? ④ 把时间当免费、忽略机会成本? ⑤ 仓位由信念强度而非赔率证据决定?

## §3 摘要层:机器装配规则

**首页零人工抄写**。决断卡五行、赚钱面板、Top3 红旗、主页 metadata 全部由装配脚本从五个 YAML verdict 块生成;人工只写 **3-5 句导读**(decision-writer 产)。

- **决断卡五行** = 五个节点的 verdict 原样带出(是不是好公司 / 在变好吗 / 贵不贵 / 扛得住吗 / 怎么办)。写手不得在正文另写一份决断卡。
- **赚钱面板** = ①质地自选的 3-5 个指标 + 一句选择理由;**结论行是引用**(质地子判定①生意模式赚钱吗、②赚钱质量真吗),面板自身零新结论。
- **Top3 风险** = 装配从红旗清单(附录D)按级别机器带出,脚本红旗与写手提名**同池排序**。
- **红标 = 纯展示层映射**:装配把 🔴/🟠 红旗反查到它涉及的指标/句子标红,🟡 标黄,🟢/ℹ️ 不标。**红标层零新增阈值**;没有红旗命中的难看数字不标色。
- **写手提名通道**:脚本测不到的真风险,写手按结构化条目(级别 + 一句证据 + 来源标"写手提名")写进**所属节点**的红旗提名里。**禁止在正文随手标红/涂色**——测不到就加 audit 规则或走提名,不给展示层开后门。

**字段定义一律以代码侧 schema 为准,本手册不复制字段表**:

| 用途 | schema 文件 |
|---|---|
| 五个节点 YAML 块 | `scripts/schemas/node-{quality,state,odds,path,decision}.schema.json` |
| 共享定义(红旗条目 / 面板指标 / 最硬证据 / 子判定 / 三元组) | `scripts/schemas/common.schema.json` |
| 装配产物(决断卡 / 面板 / Top3 / metadata / 变化区块) | `scripts/schemas/assembly.schema.json` |
| 公司级状态(runs / 增量计数 / 披露日 / 对比组) | `scripts/schemas/manifest.schema.json` |

自检命令:`{PYBIN} -m scripts.verdict_block --schema node-quality --file <你的 md>`(`--schema` 换成你的节点名,退出码 0 = 块合法)。**只有顶部那个 fenced YAML 块算数**,正文中间的块装配不读。

## §4 写作规范(全节点通用)

### 4.1 第一铁律:框架是内部思考引擎,报告输出全说人话

框架名只在小括号里淡化标注,**正文不放来源标签**(来源统一进附录E)。目标:一个没读过任何框架的人也能读顺、看懂、读完就知道"是不是好公司、该不该买、该等什么"。

**人话词典(写手必抄——左边术语 → 右边正文里就这么说)**

| 框架术语 | 报告里就这么说 |
|---|---|
| 状态后验 / λ | "公司是不是在变好、变好的'加速度'有多大" |
| 证据临界密度 / 独立证据 vs 回声 | "好消息是**实锤**(财报/订单/客户官方)还是**传闻**(券商转述/喊话),够不够多够不够硬" |
| 身份切换 P1→P4 | "市场是不是给它换了个更值钱的'身份标签',业务有没有跟上" |
| 四层验证 | "故事四关:能一句话讲清吗 → 有真订单真利润接住吗 → 有大佬/客户官方背书吗 → 价格是不是已经把好结果全买走了" |
| 赔率 / P=F+N | "把股价拆两块:现在已赚到的 + 市场为未来想象多付的;想象占比越大、越要它兑现,否则杀估值" |
| free option vs embedded obligation | "这份远期故事现在不是'白送的彩票',是'市场要求它必须做到的任务',做不到就跌" |
| 反向 DCF | "现价等于在赌它未来必须做到什么(增长/利润率/估值)——逐条看可不可信" |
| 路径可承受性 | "就算方向对,兑现前能不能扛住中途大跌/长时间不涨" |
| 幂律 / 右尾·左尾 | "是不是少数'大赢家'那一类;最坏会不会归零/腰斩" |
| 行动档位(六档) | 核心仓 / 期权小仓(博一把) / 先观察等证据 / 贵但好·不追高 / 减仓 / 回避 |
| 定价充分度 | 便宜=有安全垫 / 合理 / 已被买得差不多 / 把完美未来都买走了(极贵无垫) |

### 4.2 结论先行 + 最硬证据制

每章的形状固定:**verdict 块先行 → 子判定表(每行:判定 + 最硬的 1-2 条证据,机制在小括号里具名)→ 必要的展开段**。

"最硬"= 一手 > 二手 > 推断,且**直接支撑该判定**。凑数的第三、第四条证据不写;完整表格、时间序列、计算过程**全部下沉附录**。

### 4.3 黑白分割纪律(不许骑墙)

子判定只能是 **✓ / ⚠️ / ✗** 三态之一,verdict 只能取 §1.3 的取值域之一。禁止自造中间档、禁止"强烈看多/有条件看好/谨慎"这类连续排序,禁止任何形式的隐性打分(分数、修正系数、票数加总、"综合分 X.Y")——v8 已删除全部评分机制,复活即视为回退。

### 4.4 证据质量门控 + 证据不足的处理

- 每条证据标清来源层级:**一手**(财报/公告/PDF 原文/官方客户口径)> **二手**(券商研报/媒体转述)> **推断**(自行测算)。
- **二手转述不能单独支撑 ✓ 判定**;推断必须写出算式或口径。
- 关键证据缺失 → 判定写"不确定/数据不足",并写明**缺什么、去哪补、什么事件能补上**,把缺口带进附录E。**不许用假设数据填充**。

### 4.5 数字唯一 home + 章预算

- **数字唯一 home**:每个数字只在它的权威章或附录安家;异地出现必须是**带出处的引用**(如"拥挤结构见④/附录C")。机器装配的渲染(决断卡/面板/Top3)不受此限。
- **章预算**(§1.3 表)是软目标:超了不硬删,先自检"超出部分能不能下沉附录"。主体合计 300-400 行,附录不限长。

### 4.6 禁止项

- ❌ 写分数、权重、修正系数、综合评级、投资信号表
- ❌ 在自己节点之外下结论(尤其:仓位、行动档位、该等什么、别的节点的 verdict)
- ❌ 重新推导别的节点的判断(只能引用对方 verdict/子判定)
- ❌ 正文写来源标签(`[来源: …]`)、裸术语、"详见 §X"式的空转互指
- ❌ 手工给数字标红/涂色;正文自建红旗清单
- ❌ 复制 schema 字段表进正文,或在正文中部再放一个 YAML 块

### 4.7 BEFORE → AFTER 范例

- **BEFORE(术语堆)**:`【λ与证据临界密度】λ(向上状态跳变强度)定义…本标的属"财报型+AI receiver 混合"…[data_snapshot §2.1]`
- **AFTER(人话 + 结论先行 + 无标签)**:
  > **一句话:确实在变好,但主要是一个"小分部"在变好,最关键证据还没坐实——更像"热度先到、业绩还没跟上"。**
  > - 变好的引擎:光模块新业务,毛利率 36.7%(全公司最高)、一季度利润翻倍多。
  > - 份量还很小:只占营收 3.6%,96% 还是老本行 PCB。
  > - 证据硬不硬:关键的放量 + 大客户还是传闻,要等中报。
