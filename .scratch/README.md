# .scratch — 设计过程留档

这里不是代码,是 **v8 重构的决策记录**。代码告诉你「建了什么」,这里告诉你「**什么被否决了、为什么**」——
后者读源码读不出来,而丢了它最典型的后果不是忘记,是**把否决过的方案重新做一遍**。

## 值得读的三样

| 文件 | 是什么 | 什么时候会需要它 |
|---|---|---|
| `v8-refactor/research/01-mechanism-overlap.md` | **v8 的诊断书**:实测 v7 报告里「贵不贵」被答了约 9 次、6 套机制各答一遍同一个问题,而真正的判断只发生在三处 | 有人(包括未来的 AI 会话)提议「加个综合评分挺直观的」时 —— 这是当初删掉它的证据 |
| `v8-refactor/research/02-dongshan-walkthrough.md` | 判断链在东山精密真实数据上的完整推演(铁律要求:任何判断链设计必须先在真公司上走通) | `scripts/tests/dongshan_fixture.py` 就是从它来的;改装配层行为基线时回来对 |
| `v8-refactor/spec.md` | 九张设计票折叠后的定稿 spec | 想知道某个字段/规则「本来打算解决什么」 |

## 各票的「判断与取舍」段

被否决的方案记在这里,例如:B2 减压版否决(密度即价值)· peer-lite 轻判断管线否决
(两套判断口径必打架)· 跨行业组合视角划出 v8.0。**这些是最贵的知识。**

## 其余部分

票的状态行、进度记录、`08-RESUME.md` 这类交接便条属于过程残渣 —— git history 与 `CHANGELOG.md`
已经覆盖,留着只是懒得挑。别把它们当权威:**状态类信息以 git 与 CHANGELOG 为准**
(实测教训:票 08 的 Status 曾停在 `in-progress` 整整两周,而它当天就完成了)。
