# 05 红标机制定义

Type: grilling
Status: resolved
Blocked by: 02

## Question

「公司到底赚不赚钱」一眼可见 + 风险/特殊指标红标,具体定义:

- 「赚不赚钱」用哪几个指标回答?(真实盈利质量:扣非、现金流含量、ROIC vs WACC?)放在报告哪一层?
- 哪些指标算「风险/特殊」该红标?规则/阈值是什么?(硬规则还是写手判断?)
- 红标与 §六 红旗审计的关系:纯展示层(把已有红旗视觉化),还是新增判断规则?
- 在收敛后的判断链([判断链收敛方案](02-judgment-chain-convergence.md))中,红标处于哪一层?

## Answer

**红标定位:纯展示层映射,位于摘要/装配层,不是判断节点。** 红旗清单(audit 机制)是唯一判断权威;装配脚本把每条红旗反向映射到它涉及的指标/句子上——🔴/🟠 标红、🟡 标黄、🟢/ℹ️ 不标。红标层零新增阈值/规则;发现某类风险测不到,正确动作是给 audit 加规则(全公司生效)或走写手提名,不给红标层开后门。红标 ≠ 所有难看数字:无红旗命中的指标不标色,靠数值+peer 分位本身说话(东山 ROE 0% 分位不标色即此例)。

**「赚不赚钱」面板:菜单 + 写手自选 3-5 + 结构化输出,判断权威=质地节点。** skill 提供指标菜单(默认五件套:毛利率+净利率 / 扣非占比 / 现金含量 OCF÷净利 / FCF / ROE+peer 分位;另列行业扩展如银行 ROA/不良率);写手按公司选 3-5 个并写一句选择理由;输出固定 schema 结构化块(指标/数值/趋势/peer 分位/红标由装配反查填入),装配脚本渲染进摘要层。面板结论行直接引用质地节点子判定①「生意模式赚钱吗」+②「赚钱质量真吗」,面板自身不下任何新结论。ROIC−WACC 不做新增计算(A股 WACC 估算粗糙,伪精确)。

**写手提名通道:一张清单、两个来源。** 脚本测不到的真风险(如东山「商誉对赌未披露」,写手读 PDF 发现),写手按结构化格式(级别+证据+来源标「写手提名」)写入所属节点的红旗清单;装配对脚本红旗与提名红旗一视同仁地映射并参与 Top3 排序。写手不能在正文随手标红——提名必须落清单,双轨门关死。

**与 02 链的关系**:零冲突。红旗仍「一处权威、各归其家」(估值红旗标在赔率节点,不混入赚钱面板);面板/红旗的结构化块均为固定 schema,直接喂 04 多公司对比。schema 字段细节与视觉规范(色彩/层级/交互)分别归 /to-spec 与 07 prototype。

**铁律验收**:东山精密全套推演见 [../research/05-dongshan-panel.md](../research/05-dongshan-panel.md)——面板五行两红标一眼得出「赚得薄且不真」,与质地节点判定同源零漂移;提名商誉对赌后 Top3 与 research/02 §6 完全一致;三条新机制均未产生第二权威。
