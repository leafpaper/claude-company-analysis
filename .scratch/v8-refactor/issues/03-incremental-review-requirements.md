# 03 增量复查模式需求

Type: grilling
Status: closed (2026-08-13)

## Question

增量复查模式(对已有报告低成本刷新)的需求边界:

- 什么事件触发复查?(新财报 / 股价大波动 / 重大舆情 / 定期?)
- 复查重跑什么、复用什么?(只更数据和结论,还是重写受影响章节?)
- 产出物形态:完整新版报告,还是 delta 式「变化了什么」?
- 与现有 `--monitor`(Phase 7 量化监控)什么关系:合并、互补,还是取代?

## Answer

**核心诉求**:基本面/财报更新后,一眼看到「有什么区别、阿尔法变没变」。

1. **与 --monitor 的关系:彻底取代**。monitor 概念退役,复查是唯一模式;monitor 的「拉数据+对比+证伪检查」内核降格为复查第一阶段(分诊),旧三档结论映射为动作:无实质变化→装配盖戳 / 有变化→分层重评 / 触硬规则→建议全量。
2. **产出物 = 新版完整报告 + 首页「较上版变化」机器装配区块**:上版→本版三元组/档位对比、翻转的判断节点、触发/解除的红旗与证伪、关键指标 delta;首句人话答「阿尔法变了没」。旧版留档,发布替换。
3. **触发 = 手动 + 被动提醒**:用户看到财报/公告/异动后自己跑;系统只做报告内下次预约披露日 + Inves-Report 卡片超龄警示。不建守护进程(Hermes 联动在图外)。
4. **重跑/复用 = 固定规则分层重评**:证据层脚本全量刷新+只读新增 PDF;状态/赔率每次必重评;质地默认复用、仅分诊标脏才重评(标脏四条:年报/业务结构跨档/新红旗触及质地子判定/子判定最硬证据变号);路径每次核销证伪与左尾清单;决策层+首页永远机器重装配;章节只重写判断变了的,数据类附录脚本重生成。成本约全量 1/3。
5. **全量边界 = 硬规则 + 建议档**:基线为 v8 前旧结构→直接全量;质地翻转或档位跨两档→照常产出但首页明示「建议全量重跑」;距上次全量 >12 个月或累计 4 次增量→建议全量重锚。
6. **入口 `--review`**(自然语言「复查/更新/看看有什么变化」同触发);`--monitor` 保留为重定向别名+改名提示,一个版本周期后删。
7. **对比页联动**:复查收尾检测公司是否在 04 对比组,在→提示一句,确认后重装配对比页(卡片刷新+组内裁决重跑)。

**铁律推演**:东山精密 2026 中报场景双向推演(兑现不足→状态翻转、档位观察→回避;超预期→质地标脏重评、可能触硬规则 2),判断唯一出处保持、质地复用零漂移,见 [research/03-dongshan-incremental.md](../research/03-dongshan-incremental.md)。
