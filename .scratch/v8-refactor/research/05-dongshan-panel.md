# 05 红标机制 — 东山精密铁律推演(验收稿)

Ticket: [../issues/05-red-flag-marking.md](../issues/05-red-flag-marking.md)
数据源: 与 [02-dongshan-walkthrough.md](02-dongshan-walkthrough.md) 同源(v7.1 东山精密报告证据层 + `financial_audit.py` 现有规则)。推演目的:验证「纯展示层红标 + 菜单自选赚钱面板 + 写手提名通道」在真实公司上装得出、判得动、不产新结论。

---

## 0. 已定决策(推演的前提)

1. **红标 = 纯展示层映射**:红旗清单(audit 机制)是唯一判断权威;装配脚本把 🔴/🟠 红旗反向映射到其涉及的指标/句子上标红,🟡 标黄,🟢/ℹ️ 不标。红标层不新增任何阈值或规则;发现测不到的风险,正确动作是给 audit 加规则或走提名,不给红标层开后门。
2. **「赚不赚钱」面板 = 菜单 + 写手自选 3-5 + 结构化输出**:菜单默认五件套(毛利率+净利率 / 扣非占比 / 现金含量 OCF÷净利 / FCF / ROE+peer 分位),另列行业扩展(银行 ROA/不良率、地产回款率等);写手选 3-5 个并写一句选择理由;输出固定 schema 结构化块,装配脚本渲染。
3. **面板不下新结论**:结论行直接引用质地节点子判定①「生意模式赚钱吗」+②「赚钱质量真吗」的 verdict——「赚不赚钱」的判断权威就是质地节点,面板只是它的一眼可见化。
4. **写手提名通道**:脚本测不到的风险,写手按结构化格式(级别+证据+来源标「写手提名」)写入所属节点的红旗清单,装配对脚本红旗与提名红旗一视同仁;权威仍是一张清单,两个来源。

## 1. 面板装配(东山精密)

写手选择理由(schema 的 `industry_reason` 字段):制造业并购扩张期,矛盾焦点在现金与回报质量 → 选默认五件套(若是银行则会换 ROA/不良率,菜单机制在此分流)。

| 指标 | 数值 | 趋势/peer | 红标(装配脚本按红旗清单反查) |
|---|---|---|:---:|
| 毛利率 / 净利率 | 14.09% / 3.47% | PCB 红海常年 13~18%,定价权弱 | 无红旗 → 中性 |
| 扣非占比 | 扣非 +166.99%,非经常仅 5,061 万 | 利润是经营性实锤 | 无红旗 → 中性 |
| 现金含量(OCF÷净利) | 负(营收 +52.7% 而 OCF −17.5%) | 净利正、现金负,背离 | 🟠(audit 现金含量规则)→ **红** |
| FCF | −24.01 亿 | 扩张全靠融资 | 🟠(随现金流红旗)→ **红** |
| ROE + peer 分位 | 1.58%,peer 0% 分位 | 杜邦:改善靠杠杆 2.44→2.81 | 无对应红旗 → 中性 |
| (质地节点内)存货 | +45.1% vs 营收 +9.1% | 差 36pp 积压 | 🟡 → 黄 |

面板结论行(引用,非自产):**赚得薄(✗)· 赚得不真(✗)** ← 质地节点子判定①②。

**推演点 1 — 红标 ≠ 所有难看数字**:ROE 0% 分位很难看但现无 audit 规则命中 → 不标色,靠数值+分位本身说话。若认为该标,唯一正确动作是给 audit 加 ROE 分位规则(全公司生效),而不是这份报告手涂——Q1 决定在真实案例上的第一次约束生效。

**推演点 2 — 红旗归所属节点的指标,面板只吃属于它的**:🟠 PB 22.09(近 1 年 100% 分位)、🟠 PB/ROE 错配 25.7 倍是估值红旗,归赔率节点 → 红标出现在赔率节点的锚区间/倍数处,不混入赚钱面板。展示层映射不改变 02 定的「红旗一处权威、各归其家」。

## 2. 写手提名通道(真实案例:商誉对赌未披露)

- v7.1 中「商誉 47.69 亿,单季 +26.5 亿并购形成,**对赌条款未披露**」是写手读 PDF 发现的,`financial_audit.py` 无此规则(脚本只测商誉/净资产比例)。
- 新链处理:写手在**路径节点**红旗清单写入结构化条目——级别 🟠、证据(并购公告无对赌披露 + 商誉占比)、来源=写手提名。
- 装配结果:左尾清单①商誉减值处标红;Top3 机器带出时提名红旗与脚本红旗同池排序 → Top3 = 估值透支(🟠×2)/ 商誉 47.69 亿减值(脚本商誉规则+提名对赌合并为一条)/ 散户 2.8 倍暴增+杠杆拥挤——**与 research/02 §6 的 Top3 完全一致,零漂移**。
- 反面约束同样生效:提名必须给级别+证据并落进所属节点清单,写手不能在正文随手标红——双轨门关死。

## 3. 全链对照(验收)

| 检查 | 结果 |
|---|---|
| 面板判得动吗 | ✓ 五行数字+两个红标一眼给出「赚得薄且不真」,与质地节点「部分好——真卡位+平庸财务」的财务半边完全同源 |
| 产生新结论了吗 | ✗ 没有。结论行是质地节点引用;红标全部反查自红旗清单;面板零独立判断 |
| 与 02 链冲突吗 | 无。红标在摘要/装配层(展示),不是第五个判断节点;「赚不赚钱」权威=质地子判定①②,原本就在链里 |
| 提名通道破坏一处权威吗 | 无。清单仍一张、条目仍在所属节点唯一出现,只是来源多了「写手提名」标签 |
| 跨报告可比性(喂 04) | 面板结构化块 + 红旗清单结构化条目均为固定 schema,04 可直接抽取 |

**结论:三条新机制(展示映射/菜单面板/提名通道)全部经受住东山真实数据,可落盘。** schema 字段细节(indicator 块、red_flag_item 块)归 /to-spec。
