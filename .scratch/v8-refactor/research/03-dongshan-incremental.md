# 03 增量复查 — 东山精密铁律推演(验收稿)

Ticket: [../issues/03-incremental-review-requirements.md](../issues/03-incremental-review-requirements.md)
基线:假设东山精密已有 **v8 结构报告**(链状态取 [02 推演验收稿](02-dongshan-walkthrough.md),基准日 2026-06-22)。场景日期 2026-08 中报季——正是基线「该等什么」的真实临界点(2026 中报 + 谷歌 200G EML 验证),不是人造场景。

---

## 0. 已定决策(推演的前提)

1. **彻底取代 monitor**:monitor 概念退役,复查是唯一模式;「拉数据+对比+证伪检查」降格为复查第一阶段(分诊)。
2. **产出物 = 新版完整报告 + 首页「较上版变化」机器装配区块**(上版→本版三元组/档位对比、翻转节点、触发/解除的红旗与证伪、关键指标 delta;首句人话答「阿尔法变了没」),旧版留档,发布替换。
3. **手动触发 + 被动提醒**:用户跑 `--review`;系统只做两件被动提醒——报告写下次预约披露日、Inves-Report 卡片超龄陈旧警示。不建守护进程(Hermes 联动在图外)。
4. **固定规则分层重评**:
   - 证据层:脚本全量刷新(便宜)+ 只读新增 PDF;
   - 状态/赔率:每次必重评(价格与财报天然时变);
   - 质地:默认复用,仅分诊标脏才重评。标脏条件:(a) 年报披露 (b) 业务结构变化(关键分部占比跨档)(c) 新红旗触及护城河/管理层/财务底子子判定 (d) 质地子判定引用的最硬证据变号/跨阈值;
   - 路径:每次对照新数据核销/更新证伪清单与左尾清单;
   - 决策层 + 首页:永远机器重装配;
   - 章节:只重写判断变了的章;数据类附录(A 财务/C 舆情资金底稿)脚本重生成,B 对标随 peer 脚本刷数、叙述复用。
5. **全量边界 = 硬规则 + 建议档**:
   - 硬规则 1:基线是 v8 之前旧结构报告 → 直接全量(增量只服务 v8 结构);
   - 硬规则 2:质地判断翻转或决策档位跨两档 → 本次复查照常产出,首页明示「建议全量重跑」;
   - 建议档:距上次全量 >12 个月或累计 4 次增量 → 超龄警示升级为「建议全量重锚」。
6. **入口 `--review`**,自然语言「复查/更新/看看有什么变化」同触发;`--monitor` 保留为别名重定向 + 改名提示,一个版本周期后删。
7. **对比页联动(接 04)**:复查收尾检测该公司是否在对比组,在 → 提示一句,用户确认后重装配对比页(并排卡片刷新 + 组内裁决节点重跑一次)。

本推演要验证:分层重评规则在真实临界点场景下**推得动、判断有唯一出处、质地复用不漂移**,且两个方向(利空/利好)都成立。

---

## 1. 场景 A:中报兑现不足(利空方向)

假设:H1 光模块营收 28 亿、毛利率 33%、集团归母增速放缓至 +80%、经营现金流仍负、股价 273→210(−23%)、无商誉减值公告。

### 分诊(第一阶段,原 monitor 内核)

- 脚本全量刷新 Tushare/peer/资金流数据,diff 基线证据值;检测新增 PDF:2026 半年报 → 入读取清单。
- 对照路径节点证伪清单:**H1 光模块 <40 亿 → ❌ 触发**;毛利率 <30% → ✅ 未触;商誉减值 → ✅ 未触。
- 对照状态节点临界点:2026 中报已披露 → 临界点到达,状态必然要重判(本就是每次必重评)。
- 质地标脏检查:非年报;光模块占比 3.58%→约 7%,未跨档;无触及护城河/管理层/财务底子的新红旗;子判定最硬证据(现金流仍负、ROE 仍垫底)未变号 → **不标脏**。

### 各节点行为

| 节点 | 规则 | 本场景动作 | 结果 |
|---|---|---|---|
| 质地 | 默认复用 | 不重评;证据数字随证据层自动刷新 | 判定不变:部分好(真卡位+平庸财务) |
| 状态 | 必重评 | 临界点到达,「批量订单」传闻+「放量」被 28<40 部分证伪,实锤/传闻表更新 | **判定翻转:↑变好未确认 → λ 走弱** |
| 赔率 | 必重评 | 区间锚 [SOTP, DCF] 用 H1 数据重算;新价 210 仍为区间高端约 2.4 倍 | 判定不变:买完完美未来(数字更新) |
| 路径 | 每次核销 | 证伪清单记 ❌ 一条;散户/两融/大宗数据更新;左尾清单不变 | 判定不变:高尾险(证伪触发在案) |
| 决策层 | 机器重跑 | 三元组 [λ走弱 \| 极贵 \| 高尾险] 查映射表 | **档位 观察→回避,期权仓退出**(跨一档,不触硬规则 2) |
| 摘要层 | 机器重装配 | 决断卡重生成 + 变化区块 | 首句:「阿尔法变了:中报证伪线触发,放量故事走弱——观察下调为回避」 |

### 章节重写范围与成本

重写:②状态、⑤怎么办;轻改:③赔率(数字+锚区间更新,判定句不动)、④路径(证伪记录);不动:①质地;附录 A/C 脚本重生成,B 刷数。**约全量的 1/3 成本**(2 个节点重评 + 2 章重写 + 机器装配 vs 全量 9 个 sub-agent)。

## 2. 场景 B:超预期兑现(利好方向)

假设:H1 光模块营收 55 亿、毛利率 37%、谷歌 200G EML 验证通过、股价 273→310。

- 分诊:证伪清单 ✅ 全未触;**光模块占比跳至约 12%,跨档 → 触发标脏条件 (b) 业务结构变化 → 质地重评**。
- 质地(重评):护城河子判定「光模块仅 3.58% 未被订单坐实」的证据变号(谷歌背书+完整 H1 分部数据)→ ⚠️ 升为「部分坐实」;整体判定可能 部分好→偏好。
- 状态(必重评):传闻升实锤(叙事四关第③关补上),↑未确认 → **↑确认**。
- 赔率(必重评):F 上修、区间锚整体上移,新价 vs 新区间重判——可能仍贵但差距收窄,判定句要重写。
- 决策层:[↑确认 | 仍贵 | 高尾险] → 档位可能 观察→小仓试错;若质地同时翻转(部分好→好),**触发硬规则 2,首页明示「建议全量重跑」**——因为对标组、舆情底稿、左尾清单都建立在「PCB 为主体」的旧画像上。

**结论:链条两个方向都推得动;质地标脏规则恰好在「该重评的时刻」把质地拉回来,复用不等于冻结。**

## 3. 验收结论

1. **判断唯一出处保持**:档位变化由决策层乘法机器得出,变化区块只装配不自产;仓位仍只在决策层发声——增量模式没有制造第二个结论出口。
2. **质地复用零漂移**:场景 A 复用正确(证据未变号),场景 B 标脏正确(占比跨档+证据变号);四条标脏条件覆盖了「复用出错」的已知路径。
3. **分诊即旧 monitor 内核**:指标 diff + 证伪检查完整保留且升格为管线第一阶段,monitor 退役无信息损失;旧三档结论映射为动作(无实质变化→装配盖戳 / 有变化→分层重评 / 触硬规则→建议全量)。
4. **诚实后果**:现实中东山现有报告是 v7.1 旧结构,第一次 `--review` 撞硬规则 1 直接全量;增量从 v8 首版之后生效。
5. 存储与状态管理细节(版本文件布局、变化区块 schema、分诊脚本改造)留给 09 流水线架构切分。
