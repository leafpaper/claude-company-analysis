## Problem Statement

用户用 /company-analysis 生成投资分析报告,但 v7.1 的报告让「值不值得买」这个唯一问题被 ≥6 套机制各答一遍(评分信号、定性方向、赔率判定、行动档位、决断卡、§一结论);东山精密报告里「贵不贵」答了约 9 次、「该等什么」写了约 7 处。综合评分与定性综合方向已名存实亡(合计 5 处免责声明「这不是投资结论」却仍占主页 verdict),3 个 reviewer 里 2 个专职校验抄写一致。读者被三个「结论假面」干扰,写手与评审为复述层白白付费。

同时缺四样东西:报告打开后不能一眼决断(交付形态仍是长文档,手机上宽表格溢出、字号被压到 12px);「公司到底赚不赚钱」没有一眼可见的面板与风险红标;财报更新后只能全量重跑(--monitor 只产观察日志,不更新报告);同行之间「钱该放哪家」没有对比产品。

## Solution

把判断收敛为**一条链**:证据层 → 四问中间层(①质地=是不是好公司 ②状态=在变好吗 ③赔率=贵不贵 ④路径=扛得住吗,各一处权威)→ 决策层一处(三元组乘法 → 行动档位+该等什么+证伪)→ 摘要层(机器装配决断卡,仅 3-5 句人工导读)。报告章节=判断链本身(首页一眼结论 → 五章 → 附录 A-E),交付形态换成「仪表盘·一眼决断」(07 定稿 B 版式),手机为一等场景。

在这条链上长出四个新功能:首页「赚不赚钱」面板+红标(纯展示层映射,判断权威不变);--review 增量复查(分层重评,成本约全量 1/3,首句答「阿尔法变了没」);--compare 产业链同行对比页(机器装配并排 + 「组内裁决」具名节点);流水线随之重切为 10 agent + 依赖图两波调度,全量/增量共用。

用户视角的净效果:打开报告 30 秒内知道「怎么办、为什么、该等什么、什么情况下我错了」;财报季一条命令刷新判断;同行组一页看清钱该放哪家;每个结论全报告只在一处发声,不再有互相打架或互相抄写的第二出口。

## User Stories

1. 作为个人投资者,我想打开报告首页 30 秒内看到五行决断卡(是不是好公司/在变好吗/贵不贵/扛得住吗/怎么办),so that 我不用读完 800 行才知道结论。
2. 作为个人投资者,我想让「怎么办」给出明确行动档位、该等什么、证伪条件,so that 我知道现在做什么、等什么信号、什么情况下该认错。
3. 作为个人投资者,我想在首页看到「赚不赚钱」面板(3-5 个指标+数值+趋势+peer 分位),so that 公司真实盈利质量一眼可见。
4. 作为个人投资者,我想让被红旗命中的指标带红标(红/黄),并能反查这个红标来自哪条红旗、证据是什么,so that 我看到的是有据可查的风险而不是写手随手涂色。
5. 作为个人投资者,我想在首页看到机器从红旗清单带出的 Top3 风险,so that 最要命的风险不会被埋在正文里。
6. 作为个人投资者,我想让全报告每个判断只有一处权威出处(仓位只在决策层、「该等什么」只在状态节点、每条红旗只归家一处),so that 我不会读到互相矛盾或重复注水的结论。
7. 作为个人投资者,我想让估值锚是诚实的区间 [SOTP, DCF] 而不是单点数字,并在两法分歧大时看到分歧原因,so that 我知道估值判断的不确定性有多大。
8. 作为个人投资者,我想让任何致命红旗直接把行动档位封死在「回避」,so that 再动人的故事也压不过硬风险。
9. 作为个人投资者,我想让正文每章 verdict 先行、只留最硬证据,完整表格全部下沉附录,so that 主体 300-400 行读得完,想深挖时附录不缺料。
10. 作为手机读者,我想在 390px 宽的屏幕上正常阅读报告(瓦片单列、表格横滚、字号不缩),so that 我在通勤时也能用 Inves-Report 查判断。
11. 作为深色模式用户,我想让报告与红标在明暗两套主题下都清晰可辨,so that 夜间阅读不刺眼也不丢信息。
12. 作为色觉障碍读者,我想让红标除颜色外还有 emoji 和文字通道,so that 我不靠分辨红绿也能识别风险标记。
13. 作为财报季的持有人,我想用一条命令(--review)对已有报告做增量复查,so that 不用等一次全量重跑的时间和成本。
14. 作为财报季的持有人,我想让新版报告首页有「较上版变化」区块,首句直接回答「阿尔法变了没」,so that 我第一眼看到的是判断变化而不是数据罗列。
15. 作为财报季的持有人,我想让复查保留旧版留档,so that 我可以回看判断的演化轨迹。
16. 作为个人投资者,我想让报告写明下次预约披露日、站点卡片对超龄报告给陈旧警示,so that 我知道什么时候该回来复查,而不需要一个守护进程盯盘。
17. 作为复查用户,我想让质地判断在证据未变时直接复用、在年报/业务结构跨档/证据变号时自动标脏重评,so that 复查便宜但不冻结判断。
18. 作为复查用户,我想在质地翻转或档位跨两档时被明示「建议全量重跑」,so that 增量省钱不以判断质量为代价。
19. 作为拿不定主意的投资者,我想锚定一家公司发起产业链同行对比(--compare),系统自动查 5-8 家候选、由我确认成组,so that 「同行组里钱该放哪家」有一页直接的答案。
20. 作为对比用户,我想让对比页上半是各家决断卡机器装配并排、下半是「组内裁决」给出排序+每家一句原因,so that 既有可比的结构化事实,也有明确的相对结论。
21. 作为对比用户,我想让对比页每家标注报告基准日、超龄标「陈旧」并提示先复查,so that 我不会拿三个月前的判断跟昨天的判断硬比。
22. 作为对比用户,我想在成员报告复查完成后被提示一键重装配对比页,so that 对比结论不悄悄过期。
23. 作为节点写手 agent,我只想读链手册+本节点手册(约 300-400 行)就能开工,跨节点信息只引用对方 verdict,so that 消化成本降到旧 part3 的约 1/4,且不会重推别人的判断。
24. 作为装配脚本,我只想从五个节点 md 的 YAML verdict 块读结构化数据,so that 决断卡/面板/Top3/变化区块的生成是确定性的、可测试的、零人工抄写。
25. 作为 reviewer,我想检查「章=权威、引用不重推」这类结构性质而不是校验四套机制互抄一致,so that 评审劳力花在真问题上。
26. 作为维护者,我想让 lint 用 schema 校验、红旗闭环机检、数字唯一 home 这类机器规则兜底,so that 质量约束不依赖写手自觉。
27. 作为维护者,我想让全量与增量共用同一套「按依赖图跑任意节点子集」的调度,so that 不用维护两套流水线。
28. 作为老用户,我想在敲 --monitor 时被重定向到 --review 并得到改名提示,so that 迁移不断崖。
29. 作为报告库的主人,我想让每次 run 落在独立目录、公司级状态收在一个 manifest,so that 留档、增量计数、对比组归属有唯一真相源。

## Implementation Decisions

### 1. 判断链(核心架构,ticket 02)

- 链 = 证据层(具名机制只产证据不产结论)→ 四问中间层(各一处权威)→ 决策层一处 → 摘要层(机器装配)。
- **①质地「是不是好公司」**:五个子判定(生意模式赚钱吗/赚钱质量真吗/护城河存在吗/管理层可信吗/财务底子稳吗),✓/⚠️/✗ 三态;质地是**筛选信号,不进乘法**,决策层「好公司?」直接引用质地判定。
- **②状态「在变好吗」**:承接旧 4.11 全机制(λ/实锤传闻分级/身份切换/四关验证/无记忆性检查)+ 催化剂框架;「该等什么」(临界点)全链唯一产出处。
- **③赔率「贵不贵」**:P=F+N / 反向 DCF / ΔP / SOTP / DCF 保留为具名证据;锚改**区间锚 [SOTP, DCF]**,判定须区间两端同向;不同向 → 标「取决于口径」+ 档位保守一档(v4.2 的 20% 红线「必须重做」规则废除)。估值类红旗归家本节点。
- **④路径「扛得住吗」**:承接旧 6.4 左尾防护+高信仰体检;回报路径证据(期望收益/回撤/时间成本)归此,「建议仓位」删除;旧 6.1 快筛六项阈值并入 audit 静默机算,触发即产 🔴。
- **决策层**:三元组 [状态|赔率|路径] 乘法查行动档位映射表(六档,沿用 investment-decision-core 的映射)→ 行动档位+该等什么(引用状态)+证伪/退出;**封顶规则:任一致命红旗触发 → 档位强制封顶「回避」**;仓位唯一出处=决策层。
- **摘要层**:决断卡五行/面板/Top3/主页 metadata 全部机器装配;人工只写 3-5 句导读。主页 verdict = 行动档位人话 + 质地字段。
- **删除清单(结论假面)**:10 维评分的单维分/综合分/权重表/投资信号表、定性「综合方向」verdict、6.1 快筛章节、旧 §七 7.1-7.3 与 7.5、5.6「建议仓位」、§一人工抄写的决断卡/RATING_TRIO/one_liner。证据全部按四问归家(逐机制去向表见 issues/02)。

### 2. 报告结构(ticket 06)

- 章节=判断链:首页一眼结论(机器装配:决断卡五行→赚钱面板→Top3 红旗→3-5 句人工导读)→ ①质地 ②状态 ③赔率 ④路径 ⑤怎么办 → 附录A 财务与经营明细 / 附录B 行业与对标明细 / 附录C 舆情与资金底稿(「谁在买」证据一处权威)/ 附录D 红旗总清单(机器产物,红标与 Top3 的数据源)/ 附录E 数据来源与信息缺口。
- **最硬证据制**:每章 verdict 块先行 + 子判定表(判定+最硬证据 1-2 条,机制具名)+ 必要展开段;完整表格/时间序列/计算过程下沉附录。
- **数字唯一 home**:每个数字只在权威章或附录安家,异地必须是带来源的引用;机器装配渲染不受此限。
- **长度=软目标+章预算**:主体 300-400 行;首页≤40/质地≤70/状态≤60/赔率≤70/路径≤60/怎么办≤50;超预算不硬删,写手自检可否下沉;附录不限长。旧 9 章 33 小节的逐节去向映射见 research/06(零孤儿)。

### 3. 赚钱面板与红标机制(ticket 05)

- **红标=纯展示层映射**:红旗清单是唯一判断权威;装配把每条红旗反查映射到其涉及的指标/句子——🔴/🟠 红、🟡 黄、🟢/ℹ️ 不标。红标层零新增阈值;无红旗命中的难看数字不标色。测不到的风险→给 audit 加全局规则或走写手提名,不给红标层开后门。
- **面板=菜单+写手自选 3-5+结构化输出**:菜单默认五件套(毛利率+净利率/扣非占比/现金含量 OCF÷净利/FCF/ROE+peer 分位)+行业扩展(银行 ROA/不良率、地产回款率等);写手选 3-5 个并写一句选择理由;结论行直接引用质地子判定①②,面板自身零新结论。ROIC−WACC 不做(A股 WACC 伪精确)。
- **写手提名通道**:脚本测不到的真风险,写手按结构化格式(级别+证据+来源标「写手提名」)写入所属节点红旗清单;装配对两源红旗一视同仁,同池排 Top3。写手不得在正文随手标红。
- **面板指标块字段**(schema 契约,文件落代码侧):指标名 / 数值 / 趋势一句 / peer 分位 / 红标引用(红旗条目 id,可空)/ 备注;面板级字段:选择理由(industry_reason)、结论行引用(质地子判定①②的 verdict)。
- **红旗条目字段**:id / 级别(🔴|🟠|🟡|🟢|ℹ️)/ 标题 / 证据一句 / 来源(script|nomination)/ 归属节点(quality|state|odds|path)/ 关联指标引用(供红标反查)。

### 4. 红标视觉规范(07 遗留,本 spec 定稿)

- **三通道并行,不裸靠颜色**:emoji(🔴/🟠/🟡)+ 文字标签(如「红旗」/级别词)+ 底纹(色块背景)。stat tile 上为右上角标;表格单元格为底纹+emoji;正文行内为 emoji+下划底纹。
- **层级**:🔴/🟠 同用红色系底纹(级别靠 emoji 区分),🟡 黄色系;红黄各定一组明/暗主题 token,暗色主题降饱和提亮度,保证两主题下与正文对比度达标。
- **交互(反查)**:桌面端悬停红标弹浮层——红旗标题/级别/一句证据/来源(脚本|写手提名)/归属节点,并可点击跳附录D 对应条目锚点;触屏无悬停,红标本身即链接,点击直达附录D 条目(与「章节入口兜底」同一家族,统一实现一次)。
- 基线样张:第二套 B「仪表盘·一眼决断」(见 issues/07 所记 artifact 链接与本地 prototypes 文件);决断卡=5 张 verdict 瓦片、面板=stat tiles+红标角标、Top3=风险卡。B2 减压版已否——密度即价值,不做分层披露。

### 5. 框架文档「1+4 节点制」(ticket 08)

- `judgment-chain` 链手册=链结构唯一真理源:总公式/四问定义/决策层三元组×封顶×六档映射/摘要层装配规则/写作规范(人话词典+最硬证据制+黑白分割纪律+证据质量门控)/消化路径总表。
- 四份节点证据手册 node-quality / node-state / node-odds / node-path;**文档边界=判断节点边界=写手边界**;每份头部「你是谁/读什么/产什么」。
- **消化纪律**:写手只读链手册+本节点手册;跨节点只引用已产出 verdict/子判定,禁止重新推导;机制文本一处安家。
- schema 外置代码侧,文档只引用文件名不复制字段表(杜绝双份漂移)。
- 旧四份框架文档(scoring-rubric/qualitative-frameworks/valuation-frameworks/investment-decision-core)按 research/08 零孤儿映射重组后**直接删除**(git 即归档,不留 archive/);创业口径(C/D 轮/条款/实物期权/退出瀑布)随删,SKILL 不再问创业/上市;CHANGELOG 记一笔。

### 6. 流水线目标架构(ticket 09)

- **Agent 9→10**:data-collector(照旧+增量模式:脚本全量刷新、只下新增 PDF)/ doc-analyst(新,Phase 2 文档精析独立化,主 agent 退回纯调度)/ node-{quality,state,odds,path} 四节点写手 / decision-writer(⑤怎么办+首页导读)/ reviewer-{logic,delivery} / compare-judge。**砍**:phase3-part1-5、reviewer-{narrative,valuation,redflag}、主 agent 自跑 Phase 2、Phase 7 monitor。
- **写作顺序=依赖图两波**:质地∥赔率∥路径 并行 → 状态(体检项引用赔率 verdict)→ 决策;写作顺序≠章节顺序,排版归装配。全量/增量共用「按依赖图跑任意节点子集」一套调度。
- **产物=单文件内嵌结构化块**:每节点一个 md,顶部 fenced YAML verdict 块,正文 verdict 先行+展开段;装配与增量对比**只读 YAML 块**。节点块必含:verdict/子判定表(判定+最硬证据引用)/红旗提名;节点特有字段——质地:面板自选指标;赔率:区间锚两端+同向标记;路径:证伪与左尾清单;状态:临界点(该等什么);决策:三元组/档位/封顶检查结果。schema 文件=节点×4+装配产物(决断卡/面板/Top3/变化区块)。
- **附录 A-E 零写手全脚本装配**:A/B/C/E 挂 data-collector 整合视图;D=装配合并 audit 红旗+节点提名(两源制)。
- **状态存储=runs 目录制+manifest**:每次 run 一个日期目录(旧 run 整目录即留档);公司级 manifest 为状态唯一源(runs 列表 full/incremental、增量计数、上次全量日期、下次预约披露日、所属对比组)。
- **调度文档**(SKILL.md/agent-protocol/phase-orchestration/phases/)随本 spec 重写;phase7 文件删除。

### 7. 质量环(ticket 09)

- anti_lazy_lint 重写为 v8 lint:**删**字数下限与覆盖率规则(与上限预算/下沉附录正面冲突);**留改**外链规则、决策字段齐全(改查 YAML)、无记忆性反例;**新增**:五块 YAML schema 校验(fail)/红旗闭环机检:每条红旗一处归家+Top3 一致(fail,取代旧 redflag 人工评审)/数字唯一 home(fail)/章预算(warn)/区间锚同向标记必填(fail)。
- LLM reviewer 3→2 并行:**logic**(跨节点引用不重推/影子结论/verdict-正文自洽/最硬证据真硬/叙事 SOTP 与 N 有据)∥ **delivery**(结论先行/全说人话/对成品 HTML 做 390px 手机走查)。fresh-restart 修正循环+3 轮上限照旧,review_loop 适配新维度。

### 8. 增量复查 --review(ticket 03)

- **彻底取代 --monitor**;monitor 的「拉数据+对比+证伪检查」内核降格为复查第一阶段分诊;旧三档结论映射为动作:无实质变化→装配盖戳/有变化→分层重评/触硬规则→建议全量。--monitor 保留为重定向别名+改名提示,一个版本周期后删。
- **四段链**:R1 证据刷新(data-collector+doc-analyst 增量模式)→ R2 纯脚本分诊(triage,机检标脏四条+硬规则;规则外拿不准一律标脏,宁多重评)→ R3 依赖图跑标脏子集,未重评节点从上版拷贝 YAML 块盖「复用」戳 → R4 决策层+首页必重装配,变化区块=分诊单+新旧 YAML diff;lint+双 reviewer 不打折。
- **分层规则**:状态/赔率每次必重评;质地默认复用,标脏四条=(a)年报披露(b)关键分部占比跨档(c)新红旗触及质地子判定(d)子判定最硬证据变号/跨阈值;路径每次核销证伪与左尾清单;数据类附录脚本重生成。成本约全量 1/3。
- **产出**:新版完整报告+首页「较上版变化」区块(三元组/档位对比、翻转节点、触发/解除的红旗与证伪、关键指标 delta;首句人话答「阿尔法变了没」);旧版留档,发布替换。
- **全量边界**:硬规则1=基线为 v8 前旧结构→直接全量;硬规则2=质地翻转或档位跨两档→照常产出+首页明示「建议全量重跑」;建议档=距上次全量 >12 个月或累计 4 次增量→建议全量重锚。
- **触发**:手动 --review(自然语言「复查/更新/看看有什么变化」同触发);被动提醒仅两件——报告内写下次预约披露日、站点卡片超龄警示。不建守护进程。
- **对比联动**:复查收尾读 manifest 对比组字段,在组内→提示一句,确认后重装配对比页。

### 9. 多公司对比 --compare(ticket 04 + 遗留细节定稿)

- **定位**:产业链同行对比页,答「同行组里钱该放哪家」;同行口径=产业链相关(如东山精密↔中际旭创),非证监会窄分类。
- **流程**:`--compare <锚公司>` 发起(自然语言「和同行比比/对比」同触发)→ 自动查同行候选 5-8 家,**优先级:① Longbridge 产业链/成分股工具 ② 报告库内已有 peer 对标 ③ 模型按业务描述判断兜底** → 候选必经用户确认/增删成组。
- **组 slug**:成组确认时由用户命名;系统建议产业链主题 kebab-case 英文短名(2-4 词,模型生成),兜底 `{锚公司ticker}-peers`。
- **全报告制**:对比只在有完整报告的成员间进行;确认成组时列出缺报告成员,用户决定先跑哪几家、可分批。不建 peer-lite 管线。
- **产出=一页上下两半**:上半=各家决断卡/四问 verdict/区间锚/Top3 从各家 manifest 最新 YAML 块机器装配并排(零新判断);下半=「组内裁决」具名判断节点(compare-judge 只读各家决断卡,产排序+每家一句原因,过 schema 校验,不自产新证据)。不做完整对比报告。
- **交付**:Inves-Report 站点独立对比页(compare/{组slug}/)+本地 md 底稿,复用现有发布链路;首页对比卡与单报告卡并列,互相可点。
- **新鲜度**:每家标报告基准日;**基准日超过 90 天(约一个披露季)标「陈旧」**并提示先 --review;成员更新后手动重跑对比命令,不做自动联动。

### 10. 交付形态与移动端(ticket 07)

- 报告 HTML 换第二套 B「仪表盘·一眼决断」版式,无杂交;明暗双主题。
- 移动端一等场景:瓦片/卡片单列重排;**所有表格强制横滚容器**;正文子判定表 ≤3-4 列(全表本就下沉附录,附录宽表允许横滚);禁止缩字号硬扛(禁 12px);390px 宽走查为质量环验收项(归 reviewer-delivery)。
- 站点 index 卡片:verdict 字段=行动档位人话,新增质地字段;对比卡、陈旧警示同步进卡片模板。

## Testing Decisions

- **主测试缝(唯一)= run 目录契约**:`runs/{date}/` 内五个节点 md 的 fenced YAML verdict 块(过 schema)+ manifest + audit 红旗产物。所有确定性组件——装配(决断卡/面板/Top3/附录D 合并/变化区块)、v8 lint、triage 分诊、compare 装配——都是这个契约上的纯函数:fixture 目录进、断言产物出。不为单个内部函数另开测试缝;LLM 写手的输出质量不进单测,由 schema 校验(机器)+ reviewer-logic(评审)兜底。
- **好测试=只测外部行为**:给定一组 YAML 块 → 断言决断卡五行文本/Top3 排序/红标反查映射/变化区块首句;给定新旧两版块+证据 diff → 断言分诊单标脏结果;给定越预算/缺字段/异地数字的 fixture → 断言 lint fail/warn。不断言内部数据结构与调用路径。
- **Golden 基线=东山精密**:research/02(全量判断)、03(增量双向场景)、05(面板+提名)、06(结构映射)、09(生产者归属)五份推演稿是行为预期的权威来源;装配与分诊的 golden fixture 直接取东山数据(如决断卡五行、Top3 三条、场景A「观察→回避」、场景B 质地标脏)。
- **被测模块**:装配脚本(重写)、v8 lint(重写)、triage(monitor 内核改造)、compare 装配(新)、manifest 读写、报告解析适配。schema 文件本身以「合法/非法样例各若干」做校验测试。
- **Prior art**:scripts/tests 现有 pytest 风格——test_assemble_report.py(fixture md→装配断言)与 test_anti_lazy_lint_v7.py(fixture 报告→lint 判定)即为同缝测试,v8 沿用并替换 fixture;数据采集类测试(test_data_snapshot.py 等)不受本次影响。
- reviewer-delivery 的 390px 走查与明暗主题走查是发布链上的 agent 验收项,不进 pytest。

### 实现切分与顺序建议(供 /to-tickets)

依赖关系决定顺序,每步有独立验收:

1. **契约层**:schema 文件(节点×4+装配产物+红旗条目/面板块)+ runs 目录制 + manifest 结构 + init_run 适配。验收:合法/非法 fixture 过 schema 测试。
2. **手册层**:judgment-chain 链手册 + 四份节点手册重写,旧 references 四份及创业口径删除(按 research/08 零孤儿映射)。验收:映射表逐项核对无孤儿。
3. **全量管线**:10 agent 定义(改 data-collector、新 doc-analyst、四写手、decision-writer)+ 依赖图两波调度 + SKILL/agent-protocol/phase-orchestration/phases 重写、phase7 删除。验收:东山全量 run 产五个过 schema 的节点 md。
4. **装配层**:装配脚本重写(决断卡/面板/Top3/红标映射/附录A-E/主页 metadata)+ 报告解析适配。验收:东山 YAML fixture 装配出 research/02 §6 决断卡与 Top3(golden)。
5. **质量环**:v8 lint 重写 + reviewer-{logic,delivery} + review_loop 适配。验收:lint 新六项在正反 fixture 上判定正确。
6. **交付**:build_html B 仪表盘模板 + 明暗主题 + 红标三通道与反查 + 移动端规范 + index 卡片改版。验收:东山成品 HTML 过 390px 走查。
7. **增量复查**:triage(monitor 内核改造)+ --review 四段链 + 变化区块装配 + manifest 状态机 + --monitor 重定向。验收:东山中报双向场景重现 research/03(场景A 观察→回避、场景B 质地标脏)。
8. **对比**:compare 装配 + compare-judge + --compare 入口与成组流程 + Inves-Report 对比页 + 复查联动提示。验收:东山+中际旭创两家组装出对比页且裁决过 schema。
